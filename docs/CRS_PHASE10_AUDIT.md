# CRS 1.0 第十阶段：真实数据与审计可信度复核

审计日期：2026-11-18  
目标分支：`feature/crs-v1.0`  
范围：复核第九轮审计建议；不修改七模块、权重、评分阈值、85%发布门槛、60/40方法或NQ-Sentinel规则。

## 结论

第九轮审计的主要判断合理。第九阶段已经提供独立的FRED缓存库、授权过滤和规范化序列哈希，但当前许可批准映射为空、没有有效GitHub Actions运行证据，也没有可用的真实历史PIT数据。代码测试不能替代这些外部验收。

本阶段可在本地安全完成的改善：

1. 将缓存年龄显式拆分为 `observation_age_days` 与 `cache_retrieval_age_days`。前者仍是缓存可用性门槛的年龄口径；后者只报告距最近成功抓取的时间，不代表宏观数据变新。
2. 来源诊断新增 `publication_lag_days` 字段，仅在存在可解析的真实 `published_at` 时计算；当前FRED适配器未提供首次发布时间，因此该值保留为空。
3. JSON通过原始来源状态保留观察值年龄、普通检索年龄、缓存检索年龄和发布时间滞后字段；Markdown来源表展示这些字段，HTML沿用同一Markdown正文转义输出。
4. 修订第九阶段审计对raw SHA的描述：系统检查原始响应哈希字段格式和批次内一致性，并重算规范化观察日/值哈希；因没有保存原始HTTP响应字节，无法重新计算供应商响应哈希。两个哈希与缓存值都保存在同一个可修改DuckDB中，不能证明来源真实性或提供独立不可变性。

没有在本阶段归档真实供应商原始响应，也没有为任何FRED序列批准云端缓存。授权范围尚未逐项确认，不能把数据复制到Artifact、缓存或其他持久化位置。未来若获得许可，应把原始响应和规范化序列分开存储、各自计算哈希，并把签名/哈希清单放到权限隔离且不可变的存储中；目前这只是后续验收设计，不是已实现能力。

## 时效字段语义

| 字段 | 定义 | 当前可用性 | 使用限制 |
|---|---|---|---|
| `observation_age_days` | as-of日期减最新观察日期 | 有观察日时可计算 | 描述数据本身的时效，不代表下载时间 |
| `cache_retrieval_age_days` | as-of日期减缓存记录的retrieved_at日期 | 有检索时间时可计算 | 描述最近抓取时间，不说明该抓取是否产生新观察值 |
| `publication_lag_days` | 发布日期减观察日期 | 仅当可靠`published_at`存在时可算 | 当前FRED适配器`published_at`为空；不从观察日推断发布日期 |

现有14/35/120天缓存准入阈值继续按观察值年龄执行。本阶段不改变阈值，也不把检索年龄或发布时间滞后用于评分。
